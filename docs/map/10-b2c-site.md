# 10 — B2C Site (separate repo, separate VPS, separate database)

Hand-written pointer. The B2C map itself lives **in the B2C repo**, because duplicating ~1,800
symbols here would rot the moment either side changed.

## What it actually is

Not "a website". A full-stack application of its own:

| Part | Size | Notes |
|---|---|---|
| `src/` | 129 files, ~21k LOC | Next.js storefront + its own admin area, 58 routes |
| `backend/` | 293 files, ~44k LOC | **A fork of this repo's backend**, 493 endpoints |
| database | 85 models | Its own PostgreSQL (`b2c_db`) — different data, different server |

Repo `mg-gouda/iTourTT-B2CSite` · host `31.97.45.33` · domain transfera.ae · docker-compose
(`itourtt-b2c`, `b2c-backend`, `b2c-postgres`).

## How the two systems meet

Only through the partner seam. Nothing else is shared — no library, no database, no deploy.

```
  B2C: PublicApiService.createBooking        owns the booking (b2c_db)
         └─ PartnerClientService  ──POST /api/partner/jobs──▶  PartnerService.createJob
                                                                 owns the job (itour_db)
       JobSyncService.pollOpenJobs ◀─GET /api/partner/jobs────┘
```

**B2C owns bookings. iTourTT owns operational job status.** Job creation is idempotent on
`b2cBookingRef`, so a retried push cannot duplicate a job.

On this side the seam is `backend/src/partner/` — see `05-backend-services-portals.md`.

## The fork is stale — do not assume parity

Its backend was branched earlier and has **no counterpart** for several things that exist here:

- `JobCompletionService` — the job-status roll-up and fee materialisation
- `common/utils/service-type.util.ts` — the service-type source of truth
- `common/utils/no-show-window.util.ts` — the 80-minute no-show guard
- `sessions/` — device sessions and the REP/DRIVER single-device lock (and the `UserSession` model)

At the last comparison: **186 files byte-identical, 48 diverged, 41 B2C-only, 12 missing here.**
B2C-only modules: `public-api`, `partner-client`, `job-sync`, `website-content`, `ai-visibility`.

## Reading its map

```
ssh -i /root/.ssh/b2c_vps root@31.97.45.33
cat /opt/iTourTT-B2CSite/CODEMAP.md                      # start here
cat /opt/iTourTT-B2CSite/docs/map/00-fork-divergence.md  # then this, before editing backend/
```

Same tooling and same layout as this repo, regenerated by its own copy of
`scripts/generate-codemap.mjs` with its own pre-commit hook. Map entries carried over from this repo
for diverged files are prefixed ⚠ rather than presented as fact.

To refresh its map after changes there:

```
ssh -i /root/.ssh/b2c_vps root@31.97.45.33 'cd /opt/iTourTT-B2CSite && node scripts/generate-codemap.mjs'
```
